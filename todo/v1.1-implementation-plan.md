# Lynx v1.1 实施方案

> **交接文档**：供实现 agent 逐功能实施，审查员按本文验收。
> **卫生约束**：内部过程文档，**v1.1 打 tag 前必须从仓库移除**（v1.0 教训）。
> 最后更新：2026-08-07（v1.0.0 发布后规划）

## 0. 全局约束（所有功能必须遵守）

1. **API 冻结**：v1.0 导出符号只增不改——新包、新函数、新选项、新结构体字段（Options
   类结构体**允许追加字段**，不允许改已有字段类型/删除）。拿不准的先问审查员，
   不要自作主张改冻结面。
2. **技术基线**：Go 1.26.5（go.mod 已就位，勿动版本指令）；gofmt 1.26 规则；
   新导出符号一律中文 GoDoc（与仓库主体一致）；选项函数遵循 `WithXxx` 模式。
3. **质量门槛**：每个功能必须带回归测试（`go test -race` 通过）；涉及模块覆盖率
   不低于 70%（CI 门槛）；`go vet` / golangci-lint 无新增告警。
4. **不碰的东西**：其他功能的代码；`task release-all` 发版流程；CI 工作流
   （除非本功能明确要求）；v1.0 已定案语义（注册先于 Run、Stop-before-Start
   容忍、Start 尊重传入 ctx、Stop 有界超时）——新服务**必须**同样满足这些契约。
5. **文档同步**：每个功能更新对应 docs/ 章节（各功能节内指定）。**CHANGELOG 由
   审查员在合并时统一补记，实现 agent 不要编辑 CHANGELOG.md**（避免并行冲突）。
6. **提交规范**：中文 conventional commit，风格对齐 git log（如
   `feat(grpc): 新增 WithTLSConfig 一等 TLS 选项`）；一个功能一个分支
   （`feat/v1.1-<name>`）+ 一个功能提交（文档可并入同一提交）。
7. **依赖纪律**：优先复用现有依赖（cenkalti/backoff、otel 全家桶）；新增依赖必须
   在实现报告里说明理由；`x/time/rate` 属准标准库，F2 允许引入。
8. **验证命令**（功能完成后自测）：
   ```bash
   go build ./... && go vet ./... && go test -race -count=1 ./...   # 根模块
   gofmt -l .                                                          # 必须为空
   go mod tidy -diff                                                   # 必须为空
   ```
   contrib 内功能在对应子模块目录执行同样四步。

## 1. 实施顺序与并行性

**严格串行**：F1 → F3 → F4 → F2 → F6 → F5。原因：多功能都改 docs/05 与核心

## F1 · gRPC TLS 一等选项

**目标**：补齐 gRPC 侧 TLS 一等支持，与 HTTP 侧 `WithTLSConfig(cfg *tls.Config)`
命名/形态完全对齐（当前仅 `WithServerOptions` 逃生口，docs/05 自己也承认此缺口）。

**API 设计**（`server/grpc/server.go`）：

```go
// Options 追加字段（追加在 HealthCheckPeriod 之后）：
// TLSConfig 非 nil 时启用 TLS 传输（credentials.NewTLS），与 HTTP 侧
// WithTLSConfig 语义对齐。
TLSConfig *tls.Config

// WithTLSConfig 启用 TLS：cfg 须已装配证书（tls.LoadX509KeyPair 等）。
// 与 WithServerOptions(grpc.Creds(...)) 同时使用时，TLSConfig 优先。
func WithTLSConfig(cfg *tls.Config) Option
```

**实现要点**：

- `NewServer` 装配处：`options.TLSConfig != nil` 时把
  `grpc.Creds(credentials.NewTLS(options.TLSConfig))` 追加进 `grpcOpts`。
  import `google.golang.org/grpc/credentials`（grpc 已是依赖，无新增）。
- 优先级：TLSConfig 的 Creds 放在 `options.ServerOptions` **之后**追加即可
  （grpc.ServerOption 后者不覆盖前者，Creds 只允许一个——若用户在
  WithServerOptions 里也传了 Creds 属误用，GoDoc 注明 TLSConfig 优先：
  实现上把 TLSConfig 的 Creds 放在 ServerOptions 之**前**，grpc 以先出现的
  Creds 为准？——**实现时实测 grpc 对重复 Creds 的行为并在 GoDoc 写明**，
  测试不强制覆盖该误用路径）。

**测试**（`server/grpc/server_test.go`）：

1. `TestTLSServer`：测试内用 `crypto/tls` 生成自签证书（ecdsa + x509 模板，
   参考标准库示例，不提交证书文件），`WithTLSConfig` 起服务，
   客户端 `credentials.NewTLS(&tls.Config{InsecureSkipVerify: true})` 调
   health check 成功。
2. `TestTLSRejectsPlaintext`：同服务上明文 grpc.Dial 调用失败。
3. 现有测试全绿（零配置路径不受影响）。

**文档**：`docs/05-servers.md` gRPC 配置节补 `WithTLSConfig` 说明与示例，
并删除/更新"无 TLS 一等选项，仅逃生口"的旧表述（该表述是 v1.0 评审时刻意写
的已知限制说明，现在要反转）。

**验收**：上述测试 `-race` 通过；`go doc ./server/grpc WithTLSConfig` 可读；
docs/05 无过时表述。

## F3 · debug 管理服务（pprof）

**目标**：生产诊断开箱即用——一个可选 Service 挂载 pprof 端点。

**范围裁剪（已定案）**：v1.1 只做 pprof。**运行时日志级别调整不做**——slog/zap
logger 没有统一的级别句柄，该能力与 v1.2 配置热更新一起设计。不要顺手实现。

**API 设计**（根模块新包 `debug/`，文件 `debug/debug.go`）：

```go
// Package debug 提供运维诊断服务：pprof 端点（仅建议监听本机回环地址）。
// Service 实现 lynx.Service：Init/Start/Stop 全生命周期契约，
// Stop 容忍先于 Start 调用，Start 阻塞在传入 ctx。

func NewService(opts ...Option) *Service   // Name() == "debug"
func WithAddr(addr string) Option          // 缺省 "127.0.0.1:6060"
func WithLogger(l *slog.Logger) Option     // 缺省 Init 时取 ctx.Logger，再缺省 slog.Default()
```

**实现要点**：

- **自建 mux，不 import `net/http/pprof` 的全局 DefaultServeMux 副作用**：
  显式挂载 `pprof.Index`/`pprof.Cmdline`/`pprof.Profile`/`pprof.Symbol`/
  `pprof.Trace` + `/debug/pprof/<name>` 走 `pprof.Handler(name)`。
- 端点清单：`/debug/pprof/`（index）、`/debug/pprof/cmdline|profile|symbol|trace`、
  `/debug/pprof/heap|goroutine|allocs|block|mutex|threadcreate` 等（pprof.Handler
  按名提供）。另加 `/healthz` 返回 200 便于探活（可选）。
- 内部 `http.Server`（复用 v1.0 server/http 的 Stop 模式：Shutdown + 超时强制
  Close，但无需暴露 ShutdownTimeout 选项——固定 3s 足够，注释说明）。
- 实现 `lynx.Checker`：Start 成功后 `CheckHealth() error` 返回 nil，其余返回错误
  （对齐 schedule 的语义）。
- 日志：启动/停止各一条 Info（含 addr）。

**测试**（`debug/debug_test.go`）：

1. 起服务（`WithAddr("127.0.0.1:0")` 不可用——net/http 的 ":0" 随机端口取回
   地址需要 listener 暴露；**实现时让 Service 暴露 `Addr() string`**，Start 后
   返回实际监听地址，测试用它发请求）。
2. `GET /debug/pprof/` 200 且含 "Types of profiles available"；
   `GET /debug/pprof/heap` 200；`GET /debug/pprof/goroutine?debug=1` 200。
3. Stop 后连接被拒。
4. Stop-before-Start 不 panic（生命周期契约）。
5. `-race` 下 Start/Stop 并发交错无竞态（参考 grpc poller 的守卫模式）。

**文档**：`docs/05-servers.md` 新增节"debug 运维服务"，含**安全警示**：
缺省仅本机回环；生产环境不得将 pprof 端口暴露公网/集群外；如需远程诊断用
SSH 端口转发。`README.md` 功能清单可加一行。

**验收**：测试 `-race` 通过；`go doc ./debug` 包注释含安全警示；覆盖率 ≥70%。

## F4 · 统一错误约定（HTTP）

**目标**：为 HTTP 提供错误响应规范的最小闭环——默认 JSON 错误体 + 状态码映射
约定 + 适配 stdlib `http.Handler` 的包装器。克制范围：不做错误码体系。

**API 设计**（`server/http/errors.go` 新文件）：

```go
// ErrorHandler 处理 handler 返回的错误：写状态码与响应体。
type ErrorHandler func(ctx context.Context, w http.ResponseWriter, r *http.Request, err error)

// StatusError 由业务错误实现，声明自身对应的 HTTP 状态码；
// DefaultErrorHandler 优先取该接口，其次 500。
type StatusError interface {
    error
    StatusCode() int
}

// DefaultErrorHandler：StatusError → 其状态码，其余 500；
// 响应体统一 {"error":{"message":<err.Error()>}}（application/json）。
// 5xx 记一条 slog Error 日志（经 r.Context() 的 logger，缺省 slog.Default()）。
func DefaultErrorHandler(ctx context.Context, w http.ResponseWriter, r *http.Request, err error)

// HandleFunc 是带错误返回的业务 handler 签名。
type HandleFunc func(ctx context.Context, w http.ResponseWriter, r *http.Request) error

// NewErrorHandler 包装 fn：返回 nil 表示 fn 已自行写好响应；
// 返回非 nil 时调用 h（h 为 nil 时用 DefaultErrorHandler）；
// fn 内 panic 不在此处恢复（交给 Recovery 中间件）。
func NewErrorHandler(h ErrorHandler, fn HandleFunc) http.Handler

// WithErrorHandler 设置服务器级默认 ErrorHandler，供 NewErrorHandler
// h 传 nil 时的兜底（存入 Options，经 request ctx 或 Server 字段传递——
// 实现时选最简路径：Server 持有字段 + NewErrorHandler(nil,...) 用包级默认，
// 服务器级默认通过新增 WithErrorHandlerHandler 中间件式注入？——
// **简化决策：v1.1 只做包级 DefaultErrorHandler + NewErrorHandler，
// WithErrorHandler 服务器级选项不做**（避免 ctx 注入复杂度），
// 在 GoDoc 写明服务器级默认定位于 v1.2。
```

**实现要点**：

- 写响应前判断 `w` 是否已写过 header（`http.ResponseController` 或自记标记）：
  fn 已写响应头后再返回错误，则只记日志不改写响应，GoDoc 写明该语义。
- 5xx 日志含 method/path/status/error 四字段，经 `slog.ErrorContext(ctx, ...)`。

**测试**（`server/http/errors_test.go`）：

1. 自定义 StatusError(404) → 404 + JSON body 断言。
2. 普通 error → 500 + body。
3. fn 返回 nil → 不调用 ErrorHandler。
4. fn 已写 header 后返回 err → 不二次写 header（断言无 superfluous WriteHeader）。
5. httptest 全链路。

**文档**：`docs/05-servers.md` HTTP 节新增"错误处理约定"小节：StatusError
约定、NewErrorHandler 用法示例、与 Recovery 中间件（F2）的分工。

**验收**：测试 `-race` 通过；gofmt/golangci-lint 干净；docs 更新。

## F2 · HTTP Recovery + 限流中间件

**前置**：F4 已合并（Recovery 复用 DefaultErrorHandler）。

**API 设计**（`server/http/recovery.go`、`server/http/ratelimit.go` 新文件）：

```go
// Recovery 返回 panic 恢复中间件：捕获 handler panic，记 Error 日志
//（含 stack），经 ErrorHandler 写 500（缺省 DefaultErrorHandler）。
func Recovery(opts ...RecoveryOption) Middleware
// RecoveryOption：
func WithRecoveryHandler(h ErrorHandler) RecoveryOption

// RateLimit 返回服务器级令牌桶限流中间件：rps 为每秒放行请求数；
// 超限经 RateLimitHandler 写 429（缺省 JSON {"error":{"message":"rate limit exceeded"}}）。
// v1.1 只有服务器级全局限流；按路由/IP 限流是 v1.2。
func RateLimit(rps float64, opts ...RateLimitOption) Middleware
// RateLimitOption：
func WithBurst(n int) RateLimitOption                        // 突发容量，缺省 max(1, rps)
func WithRateLimitHandler(fn http.HandlerFunc) RateLimitOption
```

**实现要点**：

- Recovery 用 `defer recover()`；stack 取 `debug.Stack()`，日志字段
  `panic`(string) + `stack`；**recover 后必须写响应**（否则客户端挂起）。
- RateLimit 用 `golang.org/x/time/rate`（新增依赖，已在约束 7 中预批）：
  中间件实例持一个 `*rate.Limiter`（构造时 `rate.NewLimiter(rate.Limit(rps), burst)`），
  `limiter.Allow()` 为 false → 429。rps ≤ 0 时构造 panic 报明确错误。
- 两个中间件都走现有 `WithMiddleware(...)` 挂载，不改默认链（用户显式启用）。

**测试**：

1. Recovery：panic handler → 500 + JSON body + 后续请求正常（连接不被毁掉）；
   自定义 RecoveryHandler 生效；`-race` 并发 panic 无竞态。
2. RateLimit：httptest 下 burst 内全过、超出后稳定 429；自定义 handler 生效；
   rps=0 panic 断言；`-race` 并发打满无竞态。

**文档**：`docs/05-servers.md` HTTP 中间件节补 Recovery/RateLimit 用法与链序
说明（Recovery 建议声明在最外层——第一个 `WithMiddleware` 参数）。

**验收**：测试 `-race` 通过；`go mod tidy -diff` 空（x/time/rate 入 go.mod）；
docs 更新。

## F6 · 关停排水（Drain）语义

**目标**：关停时先让 readiness 失败（LB 摘流），等 drain 窗口后再真正关停，
消除关停窗口期 5xx。

**API 设计**：

```go
// options.go 追加：
DrainTimeout time.Duration   // 0 = 不启用排水（默认，向后兼容）
func WithDrainTimeout(d time.Duration) Option
```

**实现要点**（核心在 `lynx.go` 的 shutdown 路径，当前在 Run 内的 shutdown actor）：

1. `newLynx` 把一个框架内部 `drainChecker`（`atomic.Bool`）注册进 healthCheckers
   （不导出；`CheckHealth` 在 draining 置位时返回错误）。它影响的是 readiness
   聚合结果（HTTP `/healthz/readiness` 与 gRPC health 轮询都消费
   `app.HealthCheckers()`，liveness 端点**不**消费 checker 聚合——实现时确认
   server/http 两个端点对 checker 的实际消费方式，若 liveness 也聚合 checker，
   需在文档说明 drain 期间 liveness 同样失败是否可接受；**若两个端点共用同一
   聚合，v1.1 接受"drain 期间 liveness 也失败"并在 GoDoc/docs 写明**，不拆端点）。
2. shutdown 顺序改为：信号/中断到达 → 置 draining → sleep DrainTimeout →
   cancelCtx + OnStop hooks + 服务停止（现状流程）。
3. DrainTimeout 不受 ShutdownTimeout 约束（两段独立预算），GoDoc 与 docs 写明
   总关停时长上界 = DrainTimeout + ShutdownTimeout + 各服务 StopTimeout 叠加
   的既有上界。
4. `Validate` 允许 DrainTimeout 任意 ≥0（不加 MinTimeout 约束，小值合法）。

**测试**（`lynx_test.go`）：

1. 配置 DrainTimeout=200ms，跑真实 Run + 发信号（复用现有信号测试模式），
   断言：信号后约 200ms 内 HealthCheckers 聚合已不健康，而服务仍在运行
   （用探针服务记录 Start 返回时间 ≥ drain 之后）。
2. DrainTimeout=0 时行为与 v1.0 完全一致（回归）。
3. `-race`。

**文档**：`docs/03-core-concepts.md`（生命周期节）或 docs/05 健康检查节补
drain 时序图（文字版即可）；CLAUDE.md 生命周期段落如涉及时序可加一句。

**验收**：测试 `-race` 通过；DrainTimeout=0 路径与 v1.0 行为零差异（审查员
重点复核此项）。

## F5 · HTTP/gRPC client 组件（最大项，拆两个 PR）

**目标**：补齐服务间调用侧——otel 插装、trace 与日志属性传播、超时/重试默认值。
传播闭环：client 从 ctx 取 `logging.AttrsFrom` 写入请求头/metadata → 对端
`http.WithRequestID()` 透传/还原 → 全链路同 request_id。

### F5a · `client/http`（根模块新包 `client/http/`）

```go
// Package http 提供框架的 HTTP 客户端：otel 插装、trace/日志属性传播、
// 超时与重试默认值。与 server/http 相对。

func New(opts ...Option) *Client          // 零配置可用：30s 超时、无重试
// Options（全部可选）：
WithTimeout(d time.Duration)              // 整体超时，缺省 30s
WithTracerProvider(tp trace.TracerProvider) // 缺省 otel.GetTracerProvider()
WithPropagator(p propagation.TextMapPropagator) // 缺省 otel.GetTextMapPropagator()
WithRetry(maxAttempts int, backoffOpts ...)     // 缺省不重试；见下
WithClientOptions(fn func(*http.Client))        // 逃生口

// 方法：
func (c *Client) Do(req *http.Request) (*http.Response, error)
func (c *Client) Get(ctx context.Context, url string) (*http.Response, error)
func (c *Client) Post(ctx context.Context, url string, body io.Reader) (*http.Response, error)
```

**行为细则**：

- Transport：`otelhttp.NewTransport(base, otelhttp.WithTracerProvider(...),
  WithPropagator(...))`；base 为 `http.DefaultTransport` 的浅克隆（勿改全局）。
- **日志属性传播**：Do 内、otelhttp 之外，把 req.Context() 的 logging attrs
  写入 header：`logging.FieldRequestID` → `X-Request-Id`（复用
  `server/http.RequestIDHeader` 常量——允许 client/http import server/http
  只为该常量；若嫌耦合，client 包内定义同名常量并注释关联，**二选一，实现时
  定并在报告说明**）、`logging.FieldUserID` → `X-User-Id`。已存在的同名
  header 不覆盖。
- **重试**：cenkalti/backoff（已有依赖）。重试条件：传输层 error 或状态码
  {429, 502, 503, 504}；429/503 有 Retry-After 时遵守。重试前必须
  `resp.Body.Close()` 且**请求 body 可重放**（req.GetBody 非 nil 才重试带 body
  请求，否则一次不重试并记 debug 日志）。maxAttempts 含首次。
- Do 不读 body、不关 body（调用方负责），GoDoc 写明。

**测试**（httptest）：

1. 传播断言：server 侧收到 `traceparent` 与 `X-Request-Id`（ctx 预置 logging
   attrs）；已存在的 X-Request-Id 不被覆盖。
2. 超时：慢 server + WithTimeout(50ms) 报错。
3. 重试：前两次 503 第三次 200 → 成功且 attempt=3；不可重放 body 不重试。
4. `-race`。

### F5b · `client/grpc`（F5a 合并后）

```go
func Dial(target string, opts ...Option) (*grpc.ClientConn, error)  // 包装 grpc.NewClient
// Options：
WithTimeout(d time.Duration)      // 默认调用超时（per-RPC context deadline），缺省 30s
WithTLSConfig(cfg *tls.Config)    // 与 server 侧 F1 同名同义
WithTracerProvider(tp trace.TracerProvider)
WithDialOptions(opts ...grpc.DialOption)   // 逃生口
```

- stats handler：`otelgrpc.NewClientHandler(...)`；metadata 传播：
  unary/stream 两个 interceptor 把 logging attrs 写入 outgoing metadata
  （key 同字段名 `request_id`/`user_id`——metadata 不用 HTTP header 名，
  与服务端 wrapHandler 的还原逻辑**不互通**（服务端还原走消息头/metadata？
  实现时核对 server/grpc 是否还原 metadata；若不还原，v1.1 只做写入、
  服务端还原入 v1.2 backlog，并在 GoDoc/docs 写明当前边界）。
- Dial 不做连接（grpc.NewClient 惰性），GoDoc 写明。

**测试**：真实 listener 起最小 grpc server（echo metadata 的测试 service），
