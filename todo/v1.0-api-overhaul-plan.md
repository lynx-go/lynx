# Lynx v1.0 发布前 API 重构与优化方案

> 日期：2026-08-06
> 前提：**尚未正式发版，API 可自由变更，不需要向后兼容。**
> 来源：基于一次完整的架构评审（设计思路 + Go 最佳实践 + DX 三个维度），
> 并经过代码级证据核实（组件对 `App` 的实际使用面、测试 fake 成本、依赖审计）。

## 0. 设计原则（评审确认，继续遵守）

1. **零黑魔法**：无 `init()` 注册、无反射 DI、无 import 副作用；唯一的反射是
   viper/mapstructure 的配置反序列化（合理）。本方案不引入任何新的隐式机制。
2. **深模块**：核心接口保持小而深——`Component` 方法数不增加，行为（信号、
   优雅关停、健康收集、hooks、竞态防护）全部藏在实现里。
3. **DX 优先**：默认开箱即用，显式 opt-out；所有错误尽早、清晰地暴露；
   标准库接口直通（`http.Handler`、`grpc.ServerOption`、`slog.Handler`），
   保留逃逸舱口（`WithServerOptions`）。
4. **并发契约维持现状的严谨度**：注册必须先于 Run（panic）、Stop 必须容忍
   先于 Start 调用、有界停止、错误聚合上抛。这些是框架最有价值的部分，不改语义。

### 明确不做的事（评审后决定保留现状）

- `Register` 保持 fail-late 语义（错误记录、Run 时统一返回）——这是
  Wire/`boot.Bind` 人体工程学的关键，改返回 error 会让所有装配代码变啰嗦。
- `Config`/`ConfigSource` 保持 viper 形状——替换配置后端的缝是有意保留的，
  替换成本（16 个方法）在文档中说明即可。
- `boot` 包不动——46 行显式 Wire 辅助，没有简化空间。
- Run 后注册 panic（编程错误）、CLI 返回错误的不对称——有意为之，文档已述。

## 1. 核心包（根模块）——Breaking Changes

### 1.1 收窄组件接缝：新增 `Env` 接口（最高优先级）

**证据**：全库组件的 `Init` 实际只用到 `App` 的 5 个方法——`Context()`、
`Logger()`、`Config()`（zap）、`HealthCheckFunc()` + `Close()`（command）。
没有任何组件调用 `Register`/`RegisterBuilders`/`CLI`/`Run`/`OnStart`/`OnStop`/
`SetLogger`。而测试侧 `contrib/pubsub/broker_test.go:19`、`contrib/kafka/
transport_test.go:855` 的 fakeApp 都要写 12 个方法（8 个是空实现），
`contrib/zap/logger_test.go:13` 干脆嵌入 nil 的 `lynx.App` 接口（调用未覆盖
方法会 panic）——接缝过宽已经有真实的测试代价。另外 `contrib/pubsub/
broker.go:234` 的 `b.app` 字段只写不读（死字段），kafka 的 `t.app` 仅为
取一次 logger（`transport.go:257`）。

**目标设计**（`component.go`）：

```go
// Env 是框架提供给组件的运行环境。App 继承 Env；
// 组件的 Init 只依赖 Env，不依赖完整 App。
type Env interface {
    Context() context.Context
    Config() Config
    Logger(kwargs ...any) *slog.Logger
    HealthCheckers() []Checker          // 见 1.2、1.3
    Close()                             // 组件可请求关闭应用（如一次性命令执行完）
}

type LifecycleManaged interface {
    Init(env Env) error                 // 签名变更：App → Env
    Start(ctx context.Context) error
    Stop(ctx context.Context) error     // 签名变更：新增 error 返回，见 1.4
}
```

`App` 接口变为（9 方法，其中 5 个来自 Env）：

```go
type App interface {
    Env
    CLI(cmd CommandFunc) error
    OnStart(fns ...HookFunc)
    OnStop(fns ...HookFunc)
    Register(components ...Component)
    RegisterBuilders(builders ...ComponentBuilder)
    Run() error
    SetLogger(logger *slog.Logger)
}
```

影响面：`Init(app App)` → `Init(env Env)` 的所有实现与测试；zap 的
`NewLogger(app)` 等函数参数收窄为 `lynx.Env`（它们只用 Config+Context）。

### 1.2 砍掉 gocloud.dev 依赖

**证据**：整个 `gocloud.dev` 模块（依赖树庞大）只用到 `health.Checker`
（单方法接口）、`health.HandleLive`/`health.Handler`（两个 trivial handler）。
requestlog 实际已经 fork 进 `server/http/requestlog.go`（还带着两个继承来的
TODO，`requestlog.go:61,64`）。

**改动**：

- 根包新增（`health.go`）：

  ```go
  // Checker 是健康检查接口（替代 gocloud.dev/server/health.Checker）。
  type Checker interface { CheckHealth() error }
  ```

  `ServerLike` 改为 `Checker + Component`。现有 `HealthChecker` 结构体保留
  名称（实现 `Checker`），内部 `sync.RWMutex+bool` 改为 `atomic.Bool` 简化。
- `server/http`：本地实现 liveness（恒 200）与 readiness（跑全部 checker，
  任一失败返回 503 + 错误正文）handler，替换 gocloud 的两个 handler。
- `server/grpc` 用的是 `grpc_health_v1`，本就不依赖 gocloud，仅需改接口引用。
- 全部模块 `go.mod` 移除 `gocloud.dev`，`go mod tidy`。

### 1.3 `HealthCheckFunc() HealthCheckFunc` → `HealthCheckers() []Checker`

**证据**：`command.go:94` 的 `cmd.lynx.HealthCheckFunc()()` 双调用，
方法与类型同名。新设计中 `App.HealthCheckers()` 直接返回快照切片；
server 组件的 option 改为接受函数类型：

```go
type HealthCheckersFunc func() []Checker
// 使用方：http.NewServer(h, http.WithHealthCheckers(app.HealthCheckers))
// app.HealthCheckers 作为方法值天然匹配该签名
```

`command` 组件改为遍历 `env.HealthCheckers()`。删除旧 `HealthCheckFunc` 类型。

### 1.4 `Stop(ctx)` 返回 error，关停错误对称上抛

**现状不对称**：OnStop hook 的错误能上抛给 `Run()` 调用方（K8s 可感知），
组件 Stop 失败却只能落日志。**改动**：

- `LifecycleManaged.Stop(ctx context.Context) error`。
- `stopComponentBounded` 收集 Stop 返回的 error 与超时错误，写入
  `*ShutdownErrors`（已存在且并发安全），`Run()` 末尾
  `errors.Join(runG.Run(), shutdownErr, shutdownErrors)` 统一上抛。
- 所有组件实现更新签名（返回 nil 或聚合错误）。`contrib/metrics` 的 Stop
  已有 `ShutdownErrors` 聚合逻辑，正好改为返回。
- 契约不变：Stop 仍必须容忍先于 Start 被调用，文档注释保留。

### 1.5 日志统一：内化 x/log，消除双通道

**证据**：`x/log`（外部依赖 `lynx-go/x`）是对 slog 的 20 行薄封装，
`FromContext` 回落到 `slog.Default()`。框架生命周期日志走 x/log，
应用日志走 `app.logger`；`applyLogLevel`（`lynx.go:268`）只替换
`app.logger` 不调 `slog.SetDefault`，导致 `--log-level` 覆盖不到
Register/Init 阶段日志，两套 handler 并存。`SetLogger`（`lynx.go:201`）
隐式调 `slog.SetDefault` 的全局副作用未在接口注释声明。

**改动**：

- 根包内部所有 `log.InfoContext/ErrorContext(ctx, ...)`（x/log）改为
  `app.logger.InfoContext/ErrorContext(...)`。
- contrib 各包：组件在 `Init(env)` 里 `env.Logger("component", name)` 取
  logger 存字段，替换全部 x/log 调用。
- 所有模块 go.mod 移除 `github.com/lynx-go/x`，tidy。
- `SetLogger`：保留 `slog.SetDefault` 同步（用户自己的 `slog.Info` 调用
  能落到同一 logger，DX 更好），但**在接口注释中显式声明该全局副作用**。
- `applyLogLevel`：同步调用 `slog.SetDefault(app.logger)`，使 `--log-level`
  对框架与应用日志一致生效。
- 统一日志级别键解析（消除核心与 zap 两处实现、优先级相反的问题——核心
  `lynx.go:268` 顺序是 log-level→log_level→logging.level，zap
  `logger.go:19` 顺序是 logging.level→log_level→log-level）：

  ```go
  // lynx 包导出，contrib/zap 复用
  func LogLevelFromConfig(c Config) string        // 单优先级：logging.level → log-level → log_level
  func ParseLogLevel(s string) (slog.Level, error) // 现有 parseLogLevel 导出
  ```

  优先级定为 `logging.level`（结构化配置）优先，两个扁平键为兼容回退。

### 1.6 默认启用配置 flags（修复"静默失效"陷阱）

**证据**：不传 `WithUseDefaultConfigFlagsFunc()` 时 `SetFlagsFunc` 为 nil，
`initConfigure` 不解析命令行——用户敲 `-c config.yaml` 不报错也不生效，
配置悄悄没加载（`lynx.go:325-356`）。

**改动**：

- `Options.EnsureDefaults()` 中默认设置 `DefaultSetFlagsFunc` /
  `DefaultBindConfigFunc`。
- FlagSet 创建时设置 `ParseErrorsWhitelist.UnknownFlags = true`，
  忽略未知 flag（否则 `go test` 二进制里的 `-test.*` 会让 init 失败）。
- 新增 `WithDisableConfigFlags()` opt-out。
- `WithUseDefaultConfigFlagsFunc()` 删除（已被默认行为取代）。
- `--help`：pflag 返回 `ErrHelp` 时打印 usage 并以 init 错误形式返回，
  由 `Builder.Run` 处理退出码（文档说明）。

### 1.7 Options / Builder / errors 修正

- `NewOptions`（`options.go:168`）改为 `&Options{}` + `EnsureDefaults()`
  + apply opts——消除双轨默认值（现已漂移：漏 Name 和 StopTimeout）。
- 错误变量重命名：`ErrCloseTimeoutTooSmall/Large` →
  `ErrShutdownTimeoutTooSmall/Large`（字段名是 ShutdownTimeout，现名误导）。
- `Builder.Build()` 改为 `Build() (App, error)`——消除
  `builder.Build().Register(...)` nil panic 陷阱（`builder.go:51`）。
- 删除 `lynx.go:388` 的 `Option()` 死方法（导出方法挂在未导出类型上，
  不在接口中，不可达）。
- `errors.go`：删除 `wrappedError`/`errorf`，改用 `errors.New`（`errorf`
  名字暗示支持格式化，纯属误导）。
- 删除 `lynx.go:571` 的 `fn := fn`（Go 1.22+ 循环变量语义，死代码）。
- 注释去编号化：全库注释中的 "P1-1"、"P1-5"、"P2-2" 等引用指向
  `todo/v1.0-pre-release-fixes.md`（该文件不进 tag），改为自解释注释。

### 1.8 配置键命名空间

- name/id/version 读取顺序改为 `service.name`/`service.id`/`service.version`
  优先，顶层旧键回退（一个版本的过渡期，文档标注 deprecated）。
  现占用顶层通用词（`lynx.go:245-259`），易与应用配置碰撞。

### 1.9 Register 防御性校验

- `addComponents` 增加 plain nil 检查：`component == nil` 时返回
  `errors.New("lynx: cannot register nil component")`，替代运行时 panic。
  （typed-nil 无法不靠反射完全防御，文档说明 + contrib 的 `NewFromConfig`
  契约见 3.4。）

  buildHandler/shutdown 辅助函数，非必须。

## 3. contrib/ 包

### 3.1 metrics → telemetry（重命名 + 默认值修正）

- 模块目录 `contrib/metrics` → `contrib/telemetry`，包名 `telemetry`，
  go.mod module path 同步改。理由：组件名本来就是 "otel"，职责是
  trace+metrics+propagator 三件套，叫 metrics 名不副实；包名用 `telemetry`
  避免与 `go.opentelemetry.io/otel` 导入冲突。
- **默认 trace exporter 改为 noop**（不再默认 stdout pretty print——生产
  忘配 exporter 会往 stdout 倒 trace）。新增 `WithStdoutTrace()` 便捷
  option 供开发调试。metric reader 默认保持 Prometheus。
- `Init(env Env)`：env 非 nil 且未显式 `WithResource` 时，自动构建
  `resource.WithAttributes(semconv.ServiceName(NameFromContext(env.Context())))`
  ——DX 提升：服务名零配置进入 trace/metrics。
- 全局副作用（`otel.SetTracerProvider` 等）在包注释中**醒目声明**，
  并说明与 server 包显式注入策略的关系（server 不读全局、需要显式传，
  或由用户从全局取）。
- `Stop` 改返回 error（现有 ShutdownErrors 逻辑直接返回）。

### 3.2 zap

- 合并 `NewZapLogger`/`NewZapLoggerToFile`（仅 OutputPaths 不同，
  `logger.go:61-91`）为 `NewZapLogger(logLevel string, outputs ...string)`，
  默认 stdout。
- `getLevel` 改用 `lynx.LogLevelFromConfig`（见 1.5），删除本地三键循环。
- 构造函数参数从 `lynx.App` 收窄为 `lynx.Env`。

### 3.3 schedule

- `Start` 改为尊重传入的 ctx（对齐 run.Group actor 语义），不再用内部
  `s.ctx` 等待：cron.Start 后 `<-ctx.Done()` 返回 nil。`Stop` 保持
  cron.Stop + runDone 等待 + 调用方 deadline。保留 Stop-before-Start 容忍
  （原子标志与竞态测试不动）。删除为内部 ctx 服务的 `ensureCtx`/
  `context.WithoutCancel` 机制，复杂度明显下降。
- x/log → `env.Logger`；`Init` 适配 Env（容忍 nil env 的 fallback 保留，
  供脱离框架单用）。

### 3.4 kafka

- `Init`/`Stop` 签名适配；`t.app` 字段删除，logger 在 Init 时从 env 取存。
- `NewFromConfig` 的 `(nil, nil)`（未配置）契约保留，但包注释与示例中
  明确"返回 nil 时不得 Register"；配合 1.9 的 nil 检查，误注册会得到
  清晰错误而非 panic。

### 3.5 pubsub

- 删除 `broker.app` 死字段（`broker.go:234`）；x/log → env.Logger；
  签名适配。其余不动（该包评审质量最高）。

## 5. 实施顺序（接力执行用）

每个阶段完成后必须 `go build ./... && go vet ./... &&
go test -race ./...` 全绿再进入下一阶段。

- **Phase 1 核心**：1.2 Checker → 1.3 HealthCheckers → 1.1 Env →
  1.4 Stop error → 1.5 日志统一（根包部分）→ 1.6 默认 flags → 1.7 全部
  修正 → 1.8 配置键 → 1.9 nil 检查 → 注释去编号化。根模块测试同步修复。
- **Phase 2 server/**：http、grpc 适配 + 本地健康 handler + 文档修正。
- **Phase 3 contrib/**：telemetry（含目录重命名、go.work/go.mod）→
  zap → schedule → kafka → pubsub。各自测试修复。
- **Phase 4 示例与文档**：第 4 节全部。
- **Phase 5 验收**：
  1. 7 个模块（含 `_examples`）build/vet/test -race 全绿；
  2. 根与 5 个 contrib 覆盖率 ≥ 70%（CI 门槛）；
  3. `golangci-lint run` 通过；
  4. 无 `gocloud.dev`、无 `lynx-go/x` 残留依赖（`go.work.sum` tidy 后检查）；
  5. 文档中的代码示例与实际 API 一致（抽查 quick-start 全流程）；
  6. CHANGELOG 完整记录 breaking changes。

## 6. API 变更速查表

| 旧 | 新 |
|---|---|
| `Init(app App) error` | `Init(env Env) error` |
| `Stop(ctx)` | `Stop(ctx) error` |
| `App.HealthCheckFunc() HealthCheckFunc` | `App.HealthCheckers() []Checker` |
| `gocloud.dev/server/health.Checker` | `lynx.Checker` |
| `Builder.Build() App` | `Builder.Build() (App, error)` |
| `WithUseDefaultConfigFlagsFunc()` | 默认开启；`WithDisableConfigFlags()` opt-out |
| `ErrCloseTimeoutTooSmall/Large` | `ErrShutdownTimeoutTooSmall/Large` |
| `contrib/metrics`（组件名 otel） | `contrib/telemetry`，默认 trace=noop |
| `zap.NewZapLoggerToFile` | `zap.NewZapLogger(level, outputs...)` |
| `http.NewRouter()` | 删除，用 `http.NewServeMux()` |
| 顶层 `name`/`id`/`version` 配置键 | `service.*` 优先，旧键回退过渡 |
| `github.com/lynx-go/x/log` | 移除，组件用 `env.Logger()` |
